# 领域建模与建设清单

| 设备类别 | 建议规范字段 | 应重点保留的证据 |
|---|---|---|
| 视频监控 | resolution_mp、codec、fps、lens_mm、poe、power_w、ip_rating、ik_rating | 分辨率下的帧率、编码条件、ONVIF Profile、录像机兼容清单 |
| 门禁 | doors、readers、osdp_version、wiegand_bits、relay_current_a、power_v | 控制器与读卡器方向、加密支持、接线及固件条件 |
| 对讲 | sip_version、codec、poe、screen_inches、relay_outputs | SIP 注册与点对点条件、平台版本、开锁联动限制 |
| 入侵报警 | zones、bus_type、alarm_outputs、power_v、battery_ah | 总线兼容性、防区扩展条件、布防/联动限制 |

当前实现的 specs 是 JSONB，不自动校验以上字段，也不自动换算单位。类别由固定枚举限制，品牌型号精确匹配。真实入库前需要维护字段词典和型号别名。

资料审核流程：采集 → 文本/表格提取 → 结构化整理 → 人工核验来源与版本 → verified 入库 → 检索抽检。不要把销售宣传、论坛转述和官方测试清单视为同一可信度。当前审核状态由受信任维护者设置，没有独立审批系统。

未知、未公开、不支持是三个不同含义。若多个来源发生冲突，保留版本和来源，不自动以“更新日期较晚”判定真伪。当前一个设备具有多个资料版本，查询会返回各自证据，尚无自动冲突解决器。

最小验收：同品牌型号的不同资料版本可追踪；指定门禁类别时不会返回摄像机；重新入库不留下旧切片；改换 Embedding 模型即使维度相同也拒绝混用；未知兼容性不被协议相同推断为已兼容；生成回答能返回原文片段与页码/来源。

现阶段边界：未收录真实产品，未部署模型，未接入真实 API 密钥；没有自动爬虫、OCR、数值范围查询、自动自然语言条件解析、自然语言兼容关系查询、前端、多租户、批量队列和生产迁移系统。不同向量模型应建立新库重建索引。更换同一 API 路径后的底层模型也需由维护者主动重建。
