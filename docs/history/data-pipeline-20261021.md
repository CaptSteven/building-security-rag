# 答辩数据处理流程：先建立来源，再处理数据

## 当前真实状态（2026-10-21）

- 尚未爬取、清洗或切分真实厂商设备资料。
- `examples/demo-camera.json` 是程序测试用的虚构资料，不属于研究样本，不计入资料数量、产品覆盖率或评测集。
- 先前查阅的外部资料仅为技术文档：DeepSeek 官方 API 文档 https://api-docs.deepseek.com/ ，pgvector 官方项目 https://github.com/pgvector/pgvector 。二者不提供本项目的设备知识数据。
- 已有后端、资料入库、检索和模型调用代码属于后续阶段原型，不能作为已经完成真实数据工程的证据。
- 先前命令启动了本机既有 Colima 实例，拉取数据库镜像失败；详见 verification.md。当前不继续数据库或模型工作。

## 研究范围与待确定项

已确定：视频监控、门禁、对讲、入侵报警；使用关系表维护设备参数、品牌型号、协议、兼容性。

待确定：首批品牌、官方网站/官方资料入口、产品型号、文档语言、采集规模。建议从一个品牌、每类一至两份官方资料开始；这是计划，不是已有数据统计。

“清晰”暂按“清洗”理解。后续每一阶段独立执行、展示结果，不把采集、清洗和切分藏在一个入库命令内。

## 01 来源清单与爬取

输入：用户确认的官方产品页或资料下载页。

操作：
1. 核对官方域名、地区、设备类别、文档类型、页面与下载链接的对应关系。
2. 读取并记录 robots.txt 与相关使用要求。robots.txt 是采集约束之一，不等同于版权授权；记录资料用途与访问限制，不绕过登录或验证码。
3. 从来源页面发现目标文档 URL，保留链接发现记录；如直接提供 PDF，则明确记为种子 URL 下载，不冒充全站爬取。
4. 小批量、限速抓取；保存原始 HTTP 响应字节，不覆盖原文件。记录重定向和失败，禁止把下载失败算入有效样本。

输出：
- sources.csv：source_id、品牌、类别、型号、来源页 URL、下载 URL、来源类型、资料用途/授权备注。
- 原始 HTML/PDF 文件。
- 每次抓取的 metadata.json：请求 URL、最终 URL、UTC 抓取时间、HTTP 状态、Content-Type、响应大小、ETag/Last-Modified（如有）、SHA-256、爬虫版本及配置。
- crawl-log.jsonl：每次请求、重试和失败原因。原始文件使用哈希关联，不用文件名推断身份。

核验：人工打开每份小样本，与官方页面核对；统计请求数、成功数、失败数、有效文件数、重复文件数。相同 SHA-256 可去重，但不能丢失不同来源 URL 的关联。

## 02 文本提取与清洗

输入：已登记且哈希可验证的原始文件。

操作：
1. PDF 按页提取；HTML 保留标题层级与主体，导航、脚本等移除项有明确规则。
2. 保留提取后的原始文本，再生成清洗文本。换行和空白处理、重复页眉页脚识别、乱码检测分别记录，不直接覆盖。
3. 空白页、扫描件、提取异常、复杂表格进入异常清单，不能静默丢弃或用模型补写。OCR 若启用，记录引擎、版本、语言与人工校核情况。
4. 不随意改写型号、单位、数值或兼容性条件；原始表格保留页码和人工核验记录。清洗不包括模型生成参数。

输出：每页的 extracted.jsonl、cleaned.jsonl、cleaning-log.jsonl、quality-report.json。

每条清洗记录至少关联 doc_id、raw_sha256、页码或 HTML 定位、清洗规则版本、清洗前后文本哈希。清洗日志说明变化和原因；未清洗的原始提取文本永久保留。

核验：逐页对照小样本，重点检查型号、参数、单位、否定词和表格顺序；统计提取页数、空页数、异常页数、字符变化及人工修订次数。短文本不直接等价于无效文本。

## 03 文档切分

输入：已通过校核的清洗记录。

操作：
1. 优先按标题和段落边界切分；记录页码，初版尽量不跨页，避免切断参数行及兼容性条件。
2. 超长段落再按固定窗口兜底。max_chars、overlap_chars 是可复现实验参数；字符数不等于 token 数。
3. 对比小样本的不同窗口设置，再确定默认值。已有后端的 900 字符 / 150 字符重叠只是初始原型参数，未经领域实验验证。
4. 不合并不同设备型号或文档版本；不把片段数量当作产品数量。

输出：chunks.jsonl、chunking-config.json、chunking-report.json。

每个片段至少包含 chunk_id、doc_id、raw_sha256、来源 URL、标题路径、页码、cleaned_record_id、起止字符偏移、正文、正文哈希、切分器版本与配置。片段正文必须可由对应清洗文本的偏移完整重建。

核验：检查偏移回放、片段长度分布、重叠比例、是否缺失文本、是否切断参数表/条件句。只有完成实际运行后才能填写统计和展示样本。

## 可追溯链条

来源 URL → 抓取记录 → 原始文件 SHA-256 → 提取页 → 清洗记录与变更日志 → chunk_id 与偏移。

哈希用于检验字节一致性，不证明资料内容正确。URL 和抓取时间不能代替厂商发布版本。将来生成答案时还需从引用回溯到这条链。

## 执行记录要求

每轮运行建立独立 run_id，记录 UTC 时间、执行命令、代码版本或相关脚本哈希、依赖锁文件哈希、配置、输入/输出哈希、成功/失败状态和人工修订说明。失败重跑保留旧记录，不能修改日志使其看似一次成功。

答辩材料区分：计划、已实现但未运行、已运行、已人工核验。任何数量、截图、成功率、召回率都必须来自真实执行证据。
